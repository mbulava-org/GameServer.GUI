# Constants and Naming Conventions

**Last Updated:** February 2026

## Overview

This document defines naming conventions, constants, and coding standards for the GameServer.Docker project.

## ServiceLabels Constants

All Docker Swarm service labels are defined in `GameServer.Docker.Constants.ServiceLabels`.

### Available Constants

```csharp
namespace GameServer.Docker.Constants;

public static class ServiceLabels
{
    // Label to identify managed GameServer services
    public const string Managed = "gameserver.docker.managed";
    
    // Unique GameServer ID
    public const string ServerId = "gameserver.docker.Id";
    
    // GameServer display name
    public const string Name = "gameserver.docker.name";
    
    // GameServer description
    public const string Description = "gameserver.docker.description";
    
    // GameServer game type (e.g., "minecraft", "valheim")
    public const string GameType = "gameserver.docker.gametype";
    
    // Expected value for Managed label
    public const string ManagedValue = "true";
}
```

### Usage Examples

**Creating Service Labels:**
```csharp
var labels = new Dictionary<string, string>
{
    [ServiceLabels.Managed] = ServiceLabels.ManagedValue,
    [ServiceLabels.ServerId] = server.ServerId,
    [ServiceLabels.Name] = server.Name,
    [ServiceLabels.Description] = server.Description,
    [ServiceLabels.GameType] = server.GameType
};
```

**Checking if Service is Managed:**
```csharp
if (service.Spec.Labels.ContainsKey(ServiceLabels.Managed) && 
    service.Spec.Labels[ServiceLabels.Managed] == ServiceLabels.ManagedValue)
{
    // This is a managed GameServer
}
```

**Filtering by Label:**
```csharp
var filters = new ServiceFilter
{
    Label = new[] { $"{ServiceLabels.ServerId}={serverId}" }
};
```

## Naming Conventions

### Docker Resources

**Service Names:**
- Format: `{gameType}_{serverId}`
- Example: `minecraft_abc123`
- Alternative: Use `ServiceName` from GameServer model

**Volume Names:**
- Format: Auto-generated by Docker or user-specified
- Source: Can be empty for auto-creation
- Target: Game-specific (e.g., `/data`, `/config`)

**Network Names:**
- Use: `gameserver-overlay` for inter-service communication
- Type: Overlay network for multi-node support

### C# Naming

**Classes:**
- PascalCase: `GameServerManagerService`
- Suffix services with `Service`: `DockerServiceHelper`
- Suffix hubs with `Hub`: `ServerLogsHub`

**Interfaces:**
- Prefix with `I`: `IGameTypeRepository`
- Use descriptive names: `INodeAgentDiscovery`

**Methods:**
- PascalCase: `ListGameServersAsync`
- Async methods end with `Async`
- Use descriptive verb-noun pairs

**Constants:**
- PascalCase for public: `ServiceLabels.Managed`
- UPPER_SNAKE_CASE for private: `MAX_RETRY_COUNT`

**Fields:**
- camelCase with `_` prefix for private: `_dockerClient`
- PascalCase for public properties: `ServerId`

## Database Conventions

### Table Names
- Singular: `GameType`, `GameTypeExtendedMetadata`
- PascalCase

### Column Names
- PascalCase: `Key`, `DisplayName`, `ExtendedMetadataJson`
- Use full words, avoid abbreviations

### JSON Serialization
- Extended metadata stored in `ExtendedMetadataJson` column
- Use camelCase for JSON properties (Blazor convention)

## Environment Variable Names

**Standard Variables:**
- UPPERCASE_SNAKE_CASE: `SERVER_PORT`, `MAX_PLAYERS`
- Consistent with Docker and itzg/minecraft-server conventions

**Custom Variables:**
- Follow same pattern: `ENABLE_RCON`, `USE_AIKAR_FLAGS`
- Use descriptive names

## Extended Metadata DataTypes

**Valid DataType Values:**
```csharp
"string"   // Text input
"number"   // Numeric input
"boolean"  // Checkbox
"yesno"    // Yes/No dropdown or equivalent selector
"enum"     // Dropdown (requires AllowedValues)
"list"     // Comma-separated list input
"port"     // Port input with validation
"timezone" // Timezone dropdown
```

**Enum Configuration:**
```csharp
{
    "dataType": "enum",
    "allowedValues": ["option1", "option2", "option3"],
    "valueMappings": {
        "option1": "Display Label 1",
        "option2": "Display Label 2"
    }
}
```

## Radzen Component Conventions

### Template Parameters

**Always use `RenderFragment<object>`:**
```csharp
b2.AddAttribute(s2++, "Template", (RenderFragment<object>)((item) => (builder3) =>
{
    var itemStr = item?.ToString() ?? "";
    builder3.AddContent(0, itemStr);
}));
```

❌ **Don't use `RenderFragment<string>`** - causes casting errors

### TextProperty

**Use for simple property names only:**
```csharp
// ✅ Good - property name
TextProperty = "Name"

// ❌ Bad - don't use lambda
TextProperty = (item) => item.Name
```

**For custom display logic, use Template instead.**

## SignalR Hub Conventions

### Hub Names
- End with `Hub`: `ServerLogsHub`, `ResourceMonitorHub`
- Descriptive of purpose

### Hub Method Names
- PascalCase: `StreamContainerLogs`
- Start with verb: `Subscribe`, `Unsubscribe`, `Get`

### Channel Names
- Format: `{resource}-{serverId}`
- Example: `logs-minecraft_abc123`

## Code Style

### Using Statements
- Order: System, Microsoft, third-party, project
- Separate groups with blank line
- Use file-scoped namespaces (C# 10+)

### Method Length
- Keep methods under 50 lines
- Extract complex logic into helper methods
- Use local functions for small, single-use helpers

### Comments
- XML doc comments for public APIs
- Inline comments for complex logic only
- Prefer self-documenting code

### Error Handling
- Use specific exceptions: `InvalidOperationException`, `ArgumentException`
- Always log errors with context
- Provide user-friendly error messages

## Testing Conventions

### Test Method Names
- Format: `MethodName_Scenario_ExpectedBehavior`
- Example: `ListGameServersAsync_WithMultipleServers_ReturnsAllServers`

### Arrange-Act-Assert
```csharp
[Fact]
public async Task ListGameServersAsync_ReturnsOnlyManagedServers()
{
    // Arrange
    var mockClient = CreateMockDockerClient();
    var service = new DockerServiceHelper(mockClient);
    
    // Act
    var result = await service.ListGameServersAsync();
    
    // Assert
    Assert.All(result, server => 
        Assert.NotNull(server.ServerId));
}
```
